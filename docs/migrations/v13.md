# Migrating to CompoMo v13

Version 13 consolidates overlapping components and makes managed ShellApp the
standard application architecture. It intentionally does not ship
compatibility wrappers for removed components.

## Application shell

Standard applications now bind router- and product-owned data directly to
`ds-shell-app`:

```html
<ds-shell-app
  [navigation]="navigation"
  [pageChrome]="pageChrome"
  [tools]="tools"
  (dsNavSelect)="navigate($event.detail)"
  (dsTabChange)="navigate($event.detail)"
>
  <app-search slot="search-view" />
  <app-agents slot="agents-view" />
  <router-outlet />
</ds-shell-app>
```

Move primary navigation, current route/context, and account labels into
`navigation`. Move route heading, sections, depth, and actions into
`pageChrome`. Move tool items, headers, unread state, persistence, and
fullscreen configuration into `tools`.

Keep routing consequences in the application. ShellApp emits navigation intent
and owns responsive presentation, open global surfaces, mobile Inbox state,
focus restoration, and state preservation across breakpoints.

Specialized applications may set `composition="slotted"` and continue
assembling PanelNav, BarNav, PanelTools, ShellTools, ShellPage, and mobile
chrome manually. PanelTools and ShellTools remain separate public components:
PanelTools is the desktop/tablet primitive; ShellTools is the responsive
adapter.

## Select

Replace `ds-select-multi` with `ds-select multiple`.

```html
<ds-select multiple name="regions"></ds-select>
```

Assign `value` as a string in single mode and a string array in multiple mode.
Single selection closes the popup. Multiple selection keeps it open, exposes
multiselect semantics, and submits repeated form values under the field name.

## Charts and data-viz cards

Replace `ds-chart-bar-stacked` with `ds-chart-bar`:

```html
<ds-chart-bar variant="stacked"></ds-chart-bar>
<ds-chart-bar variant="percentage"></ds-chart-bar>
```

Use `variant="single"` with `data`, or stacked/percentage variants with
`series` and `categories`.

Replace `ds-card-shell-data-viz`, `ds-card-chart-bar`,
`ds-card-chart-line`, and `ds-card-chart-donut` with
`ds-card-chart`. Set `variant` to `custom`, `bar`, `line`, or `donut` and
continue supplying application-owned chart and legend data.

Donut cards with a visible legend suppress slice tooltips. The legend provides
the values and coordinates highlighting with the chart. Inactive legend rows
use 50% opacity.

## Buttons

`ds-button-filled` remains a command button. It no longer accepts `pressed`.

`ds-button-unfilled` keeps two intentionally different controlled states:

- `pressed` is only for a real toggle and supplies pressed semantics.
- `isActive` is visual composite emphasis owned by a parent widget and does not
  add toggle semantics or mutate state.

Both public tags now share internal content rendering, interaction behavior,
styling foundations, and story foundations while retaining their distinct
semantic roles.

## Removed APIs

Remove all use of:

- `ds-shell-gradient-picker`
- `ds-shell-gradient-swatch`
- Menu `gradient-picker` sections and gradient-specific events
- collection JSON aliases such as `items-json`, `headers-json`, `tabs-json`,
  and `sections-json`

Use a generic Menu `swatch-picker` section with
`shellGradientPickerSections()` for shell preferences. Assign structured
collections as JavaScript properties or framework property bindings.

## Package and build integration

Angular and React adapter source is generated under ignored internal
directories. Public imports do not change:

```ts
import { DsShellApp } from '@ds-mo/ui/angular/ds-shell-app';
import { DsShellApp } from '@ds-mo/ui/react';
```

Local package consumers should watch `dist/.package-ready.json`. It changes
only after custom elements, framework adapters, public support entries,
registry data, agent manifests, and MCP output form one coherent package.
Storybook uses the component-only `dist/.storybook-ready` boundary.

The `/shell` entry now exposes documented application contracts rather than
internal gradient geometry, transition controllers, or chrome measurement
helpers.
