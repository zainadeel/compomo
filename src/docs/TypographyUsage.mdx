# Typography usage

Use `ds-text` for product copy. A typography variant is an atomic recipe:
font size, line height, weight, and letter spacing stay together.

`@ds-mo/tokens` supplies only the primitives these recipes are built from
(`--typography-fontsize-*`, `--typography-weight-*`, and so on). It does not ship
`.text-*` utility classes, so `ds-text` is the only way to apply a complete text
style — a bare `class="text-body-medium"` styles nothing at all.

## Choose a variant

| Variant | Typical use |
| --- | --- |
| `text-body-medium` | Default product copy and standard labels |
| `text-body-small` | Helper text, metadata, and supporting copy |
| `text-body-large` | Introductory copy or a modest hierarchy increase |
| `text-title-small` | Card titles, modal titles, and compact chrome headings |
| `text-title-medium` | Section headings and expanded page regions |
| `text-title-large` | Page headings |
| `text-display-small` | Prominent summary values |
| `text-display-medium` | Rare hero metrics |
| `text-caption` | Compact labels and xs-density control text |

If no stronger hierarchy is required, start with `text-body-medium`.

```html
<ds-text variant="text-body-medium">
  Normal product copy
</ds-text>
```

## Semantics and appearance are separate

Use `as` for the correct native element and `variant` for the visual recipe.
A heading level describes document structure; it does not force a particular
visual size.

```html
<ds-text as="h1" variant="text-title-large">Page title</ds-text>
<ds-text as="h2" variant="text-title-medium">Section title</ds-text>
<ds-text as="p" variant="text-body-medium">Paragraph copy</ds-text>
<ds-text as="label" for="email" variant="text-body-small">Email</ds-text>
```

Available semantic elements are `p`, `span`, `div`, `label`, and `h1`–`h6`.

## Emphasis

`emphasis` is a boolean modifier, not a separate variant:

```html
<ds-text variant="text-body-medium" emphasis>
  Emphasized label
</ds-text>
```

Use emphasis to strengthen text within the same size tier. If the text is
actually a heading, choose the appropriate title variant instead.

Selected controls that use the shared interaction fill must not change text
weight dynamically. Selection should use the component's foreground and fill
contract while the base text recipe remains stable.

## Color hierarchy

Let text inherit the surrounding foreground by default. Use semantic `color`
values only when the text owns a clear hierarchy or intent:

```html
<ds-text color="secondary">Supporting copy</ds-text>
<ds-text color="negative">Validation error</ds-text>
```

Supported named values include `primary`, `secondary`, `tertiary`,
`quaternary`, `brand`, `negative`, `positive`, `warning`, `caution`, `ai`,
`on-strong`, `on-bold`, and `inherit`. A TokoMo custom property such as
`var(--color-foreground-secondary)` is also accepted.

`tertiary` and `quaternary` are not general low-emphasis text roles. Both are
restricted to text inside a genuinely inactive or disabled UI component, or to
purely decorative content whose removal would not change meaning, status,
hierarchy, or task understanding. Quaternary is the fainter tier. Prefer the
owning component's `isInactive` or native `disabled` state instead of manually
selecting either one. `aria-hidden` alone does not make meaningful visible text
decorative.

## Underlines and interaction

| Decoration | Meaning |
| --- | --- |
| `underline` | Default affordance for link text |
| `dotted-underline` | Hidden or supplemental interaction such as a tooltip |

Decoration is visual only; it does not make `ds-text` interactive.
The underline itself uses tertiary foreground independently from the label's
foreground, keeping the text hierarchy unchanged.

- Links are underlined by default. Brand-blue links may omit the resting
  underline when color already provides the link affordance; underlining on
  hover remains appropriate.
- A dotted underline is required when text signals hidden or supplemental
  interaction such as a tooltip. It requires an owning trigger with focus, keyboard
  interaction, and accessible tooltip or disclosure semantics.
- Do not alternate dotted and solid underlines to imply two competing actions.

## Wrapping and truncation

Use `wrap="nowrap"`, `wrap="balance"`, or `wrap="pretty"` when the text owner
has a clear layout reason. `lineTruncation` supports one through five lines:

```html
<ds-text variant="text-body-small" line-truncation="2">
  Long supporting copy
</ds-text>
```

The host needs a bounded width for truncation to occur. `ds-text` owns the
measurable text box, so apply width, flex, grid, and truncation classes directly
to it rather than adding a neutral wrapper.

## Numeric content

Use `font-feature="tabular-nums"` for columns, counters, or changing values
whose digits need stable widths.

## Interface and code families

Inter is the normal interface family through
`--typography-font-family-ui`. Code-oriented content such as `ds-code-block`,
inline prose code, fenced prose code, and structured agent tool details uses
`--typography-font-family-code` with a system-monospace fallback.

Applications own the actual font assets. Load Fira Code 400 once at the
application root to opt in; CompoMo does not bundle a font or request a CDN.
Storybook follows the same contract by importing a self-hosted development
asset in its preview rather than hiding a loader inside the component.
Its redistributed asset includes the full
[Fira Code SIL Open Font License 1.1](./licenses/FiraCode-OFL-1.1.txt).

Programming ligatures are enabled by default. Set
`--ds-code-font-variant-ligatures: none` at an application or subtree boundary
when the product needs literal glyph separation.

See the [font ownership and loading decision](https://github.com/zainadeel/compomo/blob/main/docs/font-ownership.md)
for native, Angular, and React setup; subsets, preloads, caching, CSP, offline
fallbacks, licensing, and measured network impact.

## Avoid

- `text-*` class names in `class` attributes — these are `ds-text` variant values,
  not CSS classes, and apply no styling on their own.
- Assembling `--typography-*` primitives by hand when `ds-text` can express the
  recipe.
- Overriding a variant's font size, line height, weight, or letter spacing.
- Loading Inter or Fira Code from component CSS or a feature-local selector.
- Using display variants for ordinary headings.
- Using title variants for paragraph copy.
- Using underline styles as decoration.

See **Foundation → Typography** and **Primitives → Text** for the complete
visual and component references.
