# Charts

`ds-chart` is the shared chart surface for Cartesian, polar, heatmap, and distribution compositions. D3 owns mathematical primitives and data preparation; CompoMo owns the typed grammar, renderer-neutral keyed scene, responsive guide layout, interaction semantics, accessibility, and TokoMo styling.

Install only the granular D3 packages used by an application, plus matching TypeScript packages:

```sh
npm install d3-array d3-scale d3-shape
npm install --save-dev @types/d3-array @types/d3-scale @types/d3-shape
```

## Definitions, marks, and channels

```ts
import { defineChart, dot, lineY } from '@ds-mo/ui/utils';
import { scaleLinear, scaleUtc } from 'd3-scale';

const definition = defineChart({
  marks: [
    lineY(rows, {
      id: 'actual-line',
      key: 'id',
      x: 'date',
      y: 'value',
      z: 'series',
      interactive: false,
    }),
    dot(rows, { id: 'actual-points', key: 'id', x: 'date', y: 'value', z: 'series' }),
  ],
  x: { scale: scaleUtc, axis: { label: 'Date' } },
  y: { scale: scaleLinear, nice: true, grid: true, axis: { label: 'Value' } },
  focus: 'group-x',
  tooltip: true,
});

chart.definition = definition;
```

Fields and typed accessors map ordinary rows to visual channels. Marks render in declaration order and may opt out of semantic focus with `interactive: false` when a decorative layer repeats points owned by another mark.

The Cartesian marks are `lineY`, `areaY`, `barX`, `barY`, `boxY`, `dot`, `rect`, `cell`, `ruleX`, `ruleY`, `bandX`, `bandY`, and `textMark`. Polar compositions use the `polar` container with `arcMark`, `radialLine`, `radialArea`, and `radialDot` children.

## Responsive behavior

The chart observes its container and recompiles at current CSS-pixel dimensions. It does not scale a previously rendered SVG, so caption typography, 2px data lines, grid strokes, dots, and 2px bar and arc corners remain constant.

Product layout owns available width. `ds-card-chart` owns card chrome, padding, title, and the external legend; `ds-chart` owns internal plot geometry, measured guide margins, tick thinning, and collision avoidance. Height comes from `height`, `aspectRatio`, or the 320px default.

Responsive definitions may deliberately change authored content:

```ts
const definition = defineChart(({ width, height }) => ({
  marks: width < 360 ? compactMarks : fullMarks,
  x: { scale: scaleUtc, axis: { ticks: { count: width < 360 ? 3 : 6 } } },
  y: { scale: scaleLinear, grid: height > 180 },
}));
```

The ordinary responsive path automatically reserves measured axis space and removes colliding ticks while retaining meaningful boundary ticks.

## Bars, stacks, and annotations

Use `layout: 'single'`, `'grouped'`, or `'stacked'` on bar marks. Positive and negative stacks accumulate separately, with a token-backed 1px gap at internal segment boundaries. Percentage bars use the explicit `normalizeStack` transform.

Annotations compose with data marks. Use rules for thresholds, bands for quantitative ranges, `dot` plus `textMark` for point callouts, and plot-relative text for notes. Text anchors remain contained by the resolved plot with explicit positioning available as an escape hatch.

## Pie, donut, gauge, and radar

Pie and donut are the same arc mark over a pie transform. The coordinate system owns the inner radius:

```ts
const slices = pieLayout(rows, { value: 'value', key: 'id', label: 'label' });

const donut = defineChart({
  marks: [
    polar({
      innerRadius: 0.75,
      grid: 'none',
      marks: [
        arcMark(slices, {
          key: 'key',
          theta1: 'theta1',
          theta2: 'theta2',
          z: 'label',
          value: 'value',
          label: 'label',
        }),
      ],
      center: { value: '200', caption: 'Total vehicles' },
    }),
  ],
  tooltip: true,
});
```

An inner radius of `0` produces a pie. The standard donut uses `0.75` and a token-backed 1px gap between slices. Gauges use the same arc mark with a semicircular start and end angle. Radar charts combine polygon guides with radial areas, lines, and dots. Lines use straight segments unless a curve is explicitly authored.

## Heatmaps

`cell` continuously maps its `intensity` channel from 25% to 100% fill opacity. It uses `--color-data-intent-brand` by default and accepts another TokoMo data intent. The scale depends on semantic values, not rendered width, so resizing does not change the meaning of a cell. Missing observations are omitted.

## Histograms and distributions

`binX` turns raw observations into stable numeric ranges using D3. Automatic bins depend on the data rather than container width; an application can provide an exact bin count or thresholds when comparisons require fixed ranges. Render the result with `rect`. `cumulativeBins` derives cumulative counts from the same ranges.

`densityX` prepares density samples for a straight `lineY` and optional `areaY`. `boxY` renders Tukey quartiles, whiskers, median, and outliers from ordinary grouped rows.

## Theme, formatting, and legends

The private chart-theme resolver centralizes TokoMo defaults. Data series use the twelve stable category colors. Heatmaps use data-intent colors. Chart chrome uses foreground roles: primary for axis titles and annotations, secondary for labels and zero lines, tertiary for axis/rule lines, and quaternary for grids.

Tick and annotation labels use the TokoMo caption recipe; axis titles use caption emphasis. Tooltips use body small. Typed mark paint, opacity, stroke, radius, inset, curve, and font overrides remain available without exposing arbitrary SVG attributes or scene classes.

Legends remain external and static. Compose `ds-chart-legend` from the same stable series/color mapping. It identifies series but does not hide, select, or mute them in this release.

## Focus and exact values

`nearest`, `nearest-x`, `nearest-y`, `group-x`, and `group-y` share one pointer and keyboard resolver. The chart is one tab stop; arrow keys traverse semantic points, Home and End jump, and Escape clears focus. Group focus produces one tooltip row per series and supplemental polite status text.

Tooltips supplement the visualization. When exact values are essential, provide an adjacent summary or data table that remains available without hover or focus. Advanced non-color series patterns, motion, Canvas, automatic legends, selection, brushing, zooming, maps, networks, and hierarchy layouts are follow-up work.
