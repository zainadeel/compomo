# App Shell

`ds-shell-app` is the standard application architecture for authenticated
Motive workspaces. In its default managed composition, the application supplies
three typed data objects and persistent content:

- `navigation` is router-owned primary navigation, current route/context,
  account identity, labels, and persistence configuration.
- `pageChrome` is route-owned heading, peer sections, depth/back state,
  subsections, and page actions.
- `tools` is product-owned tool definitions, headers, unread state, shortcuts,
  persistence, and fullscreen configuration.
- The optional `banner` slot holds one application-owned `ds-banner` above the
  complete navigation, workspace, and tools row.
- Named `*-view` slots hold the product-owned tool views, and the default slot
  holds the router-owned page content.

ShellApp assembles PanelNav, BarNav, ShellTools/PanelTools, MobileSheetNav,
MobileBarNav, MobileHeader, BarTitle, and ShellPage. It owns presentation state,
responsive mode, active global surfaces, direct mobile destinations, optional
Inbox grouping, focus return,
and preservation across breakpoints. The application still owns authorization,
URLs, browser history, route changes, page data, and tool data.

The canonical tool recipe pins Agents, orders Messages, Activity, then Search
in the body, and exposes Activity directly in the mobile bar. Stacks is omitted
from that recipe. Products that still need several review tools under one
mobile destination can explicitly assign those items to `mobileDestination:
'inbox'`.

Navigation events are intent-only. Handle `dsNavSelect` and `dsTabChange` with
the application router, then replace `navigation` and `pageChrome` together
from the completed route state. Do not conditionally recreate routed content or
tool views when the responsive presentation changes.

Banner visibility is also application-owned. Handle its `dsClose` event by
setting `open=false`, and keep it mounted until `dsAfterClose` when conditional
removal is required. Resolve competing global messages to one active banner;
ShellApp does not queue or prioritize them. Set Banner's `orientation` from the
application's current shell-capacity policy.

## Advanced slotted composition

Set `composition="slotted"` only when a specialized application has a verified
reason to assemble the lower-level chrome itself. PanelNav, BarNav, PanelTools,
ShellTools, ShellPage, and mobile chrome remain public primitives, but the
application then owns their cross-component state wiring.

## Gradient preference

Use `ds-swatch-picker` directly or a Menu `swatch-picker` section with
`shellGradientPickerSections()` to select the chrome wash. Applications own
preference persistence, cross-tab synchronization, and account/server
precedence; ShellApp paints the resolved preference.
